System Designer

Starting from the base project, I established the overall structure for the game's files and systems, connecting everything through a unified map architecture managed by a central manager. This allowed us to configure maps by specifying which map to load, how many enemies to spawn, and which enemy types to include, all through the system's configuration.

I also designed and implemented the turn-based combat system, from defining its core mechanics and dependencies to building a functional foundation for the gameplay.

During implementation, I encountered challenges with keeping the entire combat architecture inside a single Blueprint. To make the system more modular and maintainable, I split it into smaller, specialized managers:

Arena Manager: Controls turn order and manages combat progression.
UI HUD Manager: Communicates gameplay events to the relevant UI widgets, keeping the interface updated with the current combat state.
Camera Manager: Controls camera movement and positioning during combat.

This modular architecture made the system easier to maintain and allowed individual components to handle their responsibilities independently.

UI Programming

Since the game relied heavily on UI widgets, I needed to develop a scalable and organized system that would be easy to maintain and expand.

I divided the UI into two main categories: Main Widgets and Additional Widgets.

Main Widgets: A persistent set of widgets that remain visible throughout combat, providing players with essential information.
Additional Widgets: Widgets that appear and disappear as players switch between different interactions.

This structure kept the interface organized and made it easier to manage which elements were displayed at any given time.

As the project grew, loading all the necessary assets without causing performance issues became a challenge. To address this, I implemented a loading screen that checks whether the required map assets have finished loading before allowing the screen to disappear.

Animation Implementation

The game features over 30 animation sequences, six sequences per player character alongside animations for enemies. I primarily worked on implementing character animations, as well as few enemy animations.

Many of these sequences required additional programming to synchronize animations with gameplay events. This included triggering Quick Time Events at the correct moments and notifying the enemy's systems when they received damage.

We used a shared skeleton. Animations created for other skeletons were retargeted to this common skeleton, allowing them to be integrated into the existing animation system.
